# INSTANT DDL (MySQL 8.0.12+ / 확장 8.0.29+)

`ALTER TABLE`로 컬럼을 추가/삭제할 때 **테이블 데이터는 하나도 안 건드리고, 데이터 딕셔너리(메타데이터)만 고쳐서** 끝내는 방식. 테이블이 1억 건이든 10건이든 거의 즉시(밀리초) 끝난다. 핵심 질문은 "데이터를 안 건드리는데 어떻게 컬럼이 늘고 주는가"이고, 답은 **물리적으로 저장된 행과 논리적 스키마를 분리**하는 트릭에 있다.

## 세 가지 알고리즘 중 제일 싼 것

MySQL의 `ALTER TABLE`은 비용이 다른 3단계가 있다. 책에 새 항목을 끼워넣는 방법에 빗대면:

| 알고리즘 | 하는 일 | 비유 | 동시 DML |
|---|---|---|---|
| `COPY` | 임시 테이블 통째로 만들고 전 행 복사 후 교체 | 책을 처음부터 새로 다 베껴 씀 | 쓰기 차단 |
| `INPLACE` | 자리에서 재구성(클러스터 인덱스 리빌드 등) | 책을 뜯어 페이지 재정렬 | 대체로 허용 |
| `INSTANT` | **데이터는 그대로, 목차(메타데이터)만 수정** | 책 앞 목차에 "N번째 항목 추가" 한 줄만 적음 | 허용, 거의 즉시 |

MySQL은 기본적으로 **가능하면 INSTANT를 자동 선택**하고, 안 되면 INPLACE → COPY로 내려간다. 이건 Oracle 튜닝에서 보던 메모리/조인 얘기와는 층이 다른, 스키마 변경 시점의 이야기다.

## 어떻게 데이터를 안 건드리나

### 8.0.12 — 맨 뒤 컬럼 추가만

컬럼 `c`를 추가해도 기존 행에는 `c`가 물리적으로 **없다**. 대신:

1. 딕셔너리에 "`c`의 기본값 = X"만 기록.
2. **읽을 때** 옛 행에 `c`가 없으면 → 저장해둔 기본값 X를 대신 반환.
3. **새 행**은 그때부터 `c`를 물리적으로 포함해 저장.

옛 행과 새 행이 물리적으로 다른 모양인데, 읽기 시점에 메타데이터로 메꿔 똑같아 보이게 한다. 단 이 버전은 **맨 끝 추가만** 가능 — 삭제·중간 삽입을 하면 컬럼 위치 번호가 밀려서 옛 행을 해석 못 하니까.

### 8.0.29 — 임의 위치 추가 + 삭제 (row versioning)

8.0.29가 넣은 게 **행 버전(row version)**. 이게 확장의 핵심이다.

- 각 물리 행이 **자기가 어느 스키마 버전으로 쓰였는지** 레코드 헤더에 버전 번호를 단다.
- 딕셔너리는 **버전별 컬럼 배치도**를 들고 있다: "버전 0 = [a,b,c], 버전 1 = b 삭제되고 x가 2번째 삽입…".
- INSTANT로 중간 삽입/삭제를 할 때마다 테이블의 **현재 버전이 +1**.

읽을 때 흐름(중간 상태를 다 펼치면):

```
디스크에서 행 하나 읽음
 → 헤더의 row version = 0 (옛날 행)
 → 딕셔너리: "버전 0 배치 = [a, b, c]"
 → 현재 스키마(버전 1) = [a, x, c]   (b 삭제, x 삽입)
 → 매핑: a 그대로 / b 버림 / x 없으니 기본값 / c 그대로
 → 논리적 행 [a, x-default, c] 로 재구성해서 반환
```

**옛 행은 옛 모양 그대로 디스크에 남고**, 새 행은 새 모양으로 쌓이며, 버전 번호 + 버전별 배치도가 둘 사이를 통역한다. 전체 테이블을 다시 쓸 필요가 없어 즉시 끝난다.

## 공짜는 아니다 — 대가와 한계

원리를 알면 한계가 자연스럽게 보인다.

- **버전 상한 64**: instant 컬럼 추가/삭제는 누적 64번까지. 배치도를 무한히 쌓을 수 없으니. 한도에 닿으면 `ALGORITHM=INPLACE/COPY`로 한 번 리빌드해 버전을 0으로 리셋해야 한다.
- **삭제해도 공간이 즉시 안 줄어듦**: INSTANT DROP은 "이 컬럼 무시해"라고 표시만 한다. 옛 행 속 그 데이터는 물리적으로 남아 있고, 실제 회수는 나중 테이블 리빌드 때.
- **읽기 시 미세 오버헤드**: 매 행마다 버전 매핑을 해석. 보통 무시할 수준.
- **INSTANT 불가 케이스**: 컬럼 타입 변경, 일부 압축 테이블 등 → 자동으로 INPLACE/COPY.

## 실무 사용

```sql
-- 명시적으로 강제 (안 되면 즉시 에러 → 조용히 무거운 방식으로 안 떨어짐)
ALTER TABLE orders ADD COLUMN memo VARCHAR(200) AFTER status, ALGORITHM=INSTANT;

ALTER TABLE orders DROP COLUMN memo, ALGORITHM=INSTANT;   -- 8.0.29+
```

`ALGORITHM=INSTANT`를 명시하면 불가능할 때 무거운 방식으로 몰래 떨어지지 않고 **에러를 던진다** — 운영 중 대형 테이블에 락 거는 사고를 막아준다. 실무에선 명시를 권장.
