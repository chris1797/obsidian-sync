# MCP MOC

이 영역의 입구. 핵심 축은 **"창구는 하나, 나머지는 전부 그 창구에 내미는 데이터"** — 프로토콜 이해도, 서버 만들기도, 규모가 커졌을 때의 문제도 결국 그 창구에 무엇을 얼마나 실어 보내느냐로 갈린다.

## 읽는 순서

1. [[MCP]] — 먼저 여기. REST 와 뭐가 다른지(문패 vs 민원 창구), 전송 방식(stdio / Streamable HTTP), 두 통로의 분리까지. 나머지 노트가 전부 이 비유 위에 얹힌다.
2. [[MCP 서버 로컬 개발 루프]] — 직접 만들 때. 툴을 추가하고 확인하는 한 바퀴와, 화면이 없는 물건이라 생기는 함정들.
3. [[MCP Python SDK 2.x — FastMCP 에서 MCPServer 로]] — 파이썬 공식 SDK 의 세대 교체. 이관하며 드러난 "설정이 놓이는 자리" 문제.
4. [[FastMCP 대규모 도구의 토큰 절약]] — 툴이 수백 개로 늘었을 때. 창구에 실려 가는 설명서의 양을 줄이는 장치들.
5. [[MCP 서버 조합 (프록시·집계)]] — 내 서버가 남의 MCP 서버를 물 때. 4번의 툴 폭증이 여기선 기본값이 된다.

1→2 는 "이해 → 제작", 4→5 는 "규모 → 아키텍처" 로 짝이다. 3 은 파이썬으로 만들 때만 필요하니 건너뛰어도 흐름이 끊기지 않는다.

## 다음 가지 후보

`resources`·`prompts`(툴 말고 다른 노출 방식), 원격 서버 인증(OAuth) 상세, MCP Inspector, 툴 응답 포맷 설계, 클라이언트 쪽 구현(내가 남의 서버를 부를 때).
