# MCP Python SDK 2.x — FastMCP 에서 MCPServer 로

공식 SDK(PyPI `mcp`)가 2.x 로 올라가면서 **`mcp.server.fastmcp` 모듈이 통째로 사라졌다.** 1.x 에서 서버를 만들던 `FastMCP` 클래스가 없어지고 `mcp.server.mcpserver.MCPServer` 로 대체됐다. import 한 줄만 바꾸면 끝날 것 같지만, 실제로 이관해보면 **설정이 놓이는 자리가 바뀌는 것**이 진짜 변경이다.

> 헷갈리는 지점 먼저 — 여기서 말하는 FastMCP 는 **공식 SDK 안에 들어 있던** `mcp.server.fastmcp.FastMCP` 다. [[FastMCP 대규모 도구의 토큰 절약]] 에서 다룬 독립 패키지 `fastmcp`(gofastmcp.com) 와는 이름만 같고 계보가 다르다. 이름이 같아서 버전 얘기를 할 때마다 서로를 오해하게 된다.

## 표면 — 옮기는 건 어렵지 않다

API 모양은 거의 그대로다. `@mcp.tool("이름")` 데코레이터, `await mcp.list_tools()`, `mcp.streamable_http_app()`, `mcp.sse_app()`, `mcp.run(transport=...)` 가 전부 같은 이름으로 있다. 그래서 `FastMCP("서버명")` → `MCPServer("서버명")` 한 줄이면 서버는 뜬다.

의존성은 같이 끌려 올라간다. 2.x 는 `sse-starlette>=3.0.0`, `uvicorn>=0.31.1` 을 요구해서, 이 핀들을 안 올리면 의존성 해결 단계에서 막힌다. 오히려 이건 친절한 실패다 — **설치가 안 되니까 바로 안다.**

## 진짜 변경 — 전송 보안 설정이 생성자에서 앱 팩토리로 갔다

1.x 는 서버 인스턴스를 만들 때 전송 보안 설정을 같이 넣었다. DNS rebinding 보호(Host/Origin 헤더 검증)를 켜는 설정인데, [[MCP]] 에서 정리한 대로 원격 전송(Streamable HTTP)은 아무나 붙을 수 있는 "로비 안내데스크" 라서 이런 문지기가 필요하다. 브라우저 쪽 같은 방어를 [[CORS]] 가 맡는다면, 이건 서버가 직접 Host 를 확인하는 쪽이다.

```python
# 1.x — 인스턴스가 설정을 들고 있다
mcp = FastMCP("서버명", transport_security=TransportSecuritySettings(...))
```

2.x 에는 이 생성자 인자가 없다. 설정 클래스(`TransportSecuritySettings`)는 그대로 남아 있는데, **받는 쪽이 앱을 만드는 함수로 내려갔다.**

```python
# 2.x — 앱을 만들 때 넘긴다
app = mcp.streamable_http_app(transport_security=TransportSecuritySettings(...))
```

기능은 같다. 그런데 **틀리는 방식이 달라진다.**

## 왜 이 이동이 위험한가 — 빠뜨려도 조용히 통과한다

생성자에 있을 때는 인스턴스가 하나뿐이라 설정도 하나뿐이었다. 어디서 앱을 만들든 보호가 따라왔다. 앱 팩토리로 내려간 뒤로는 **`streamable_http_app()` 를 인자 없이 부르면 보호가 없는 앱이 조용히 만들어진다.** 서버는 정상적으로 뜨고, 로그도 깨끗하고, 툴도 전부 잘 돈다. 아무도 두드리지 않는 동안에는 보호가 있는 서버와 없는 서버가 **완전히 같은 모습**이다.

이건 [[침묵은 정상으로 오해받는다]] 와 같은 뿌리다. 거기서는 "돌지 않았다" 와 "돌았는데 결과가 이렇다" 가 겹쳤는데, 여기서는 **"막고 있다" 와 "안 막고 있다" 가 겹친다.** 실패 모드를 일부러 만들어보기 전까지 드러나지 않는다.

일반화하면 이렇다. **필수 설정이 "생성자 인자" 에서 "호출 인자" 로 내려가면, 빠뜨림이 에러에서 침묵으로 바뀐다.** 생성자는 객체가 하나라 한 번만 통과하면 되지만, 호출은 여러 곳에서 일어나고 그중 하나만 빠뜨려도 그 경로가 무방비가 된다.

## 대응 — 경로를 하나로 묶고, 배선을 테스트로 잠근다

그래서 앱 생성 경로를 함수 하나로 좁혔다. 서버 모듈에 설정을 상수로 두고, 앱은 반드시 이 함수를 거쳐 만들게 한다.

```python
TRANSPORT_SECURITY = TransportSecuritySettings(...)   # 설정은 한 곳에

def build_http_app(transport: str):
    """보안 설정을 반드시 걸어서 앱을 만든다. 진입점은 이 함수만 쓴다."""
    if transport == "streamable-http":
        return mcp.streamable_http_app(transport_security=TRANSPORT_SECURITY)
    return mcp.sse_app(transport_security=TRANSPORT_SECURITY)
```

그리고 테스트를 **설정값**만 보지 말고 **배선**까지 보게 했다. "보호가 켜져 있다" 는 단언은 상수만 확인하므로, 그 상수가 실제로 앱에 전달되는지는 증명하지 못한다. 앱 빌더를 가로채(mock) `transport_security` 인자를 받고 호출되는지 확인하면 그제서야 잠긴다.

이게 [[정본은 하나, 나머지는 가리킨다]] 의 코드판이다 — 설정의 정본을 한 곳에 두고, 그 정본을 거치지 않는 경로를 아예 없앤다.

## 또 하나 — 객체 표현과 프로토콜 표현이 갈라졌다

2.x 는 파이썬 객체의 필드 이름을 스네이크 케이스로 바꿨다. `tool.inputSchema` → `tool.input_schema`, `outputSchema` → `output_schema`. 그런데 **와이어로 나가는 JSON 은 여전히 `inputSchema`** 다. 직렬화할 때 별칭(alias)으로 원래 이름을 돌려준다.

프로토콜이 정한 이름은 못 바꾸니까(바꾸면 모든 클라이언트가 깨진다) 파이썬다움만 안쪽에서 챙긴 것이다. 그래서 이관할 때 판별식이 하나 생긴다 — **"이건 객체를 가리키나, 메시지를 가리키나."** 코드에서 속성으로 접근하는 곳은 바꾸고, 문서에서 "LLM 에 전달되는 건 name·description·inputSchema 셋뿐" 같이 프로토콜을 서술하는 곳은 **그대로 둬야** 한다. 일괄 치환하면 문서 쪽이 거짓이 된다.

## 보안 버전을 되돌리는 게 아닌지 확인하는 법

2.x 로 올리는 게 곧 최신이라고 믿으면 안 된다. 1.x 계열에 보안 패치를 이유로 하한선을 박아둔 프로젝트라면, **그 패치가 2.x 에도 들어 있는지**를 따로 확인해야 한다. 이번 경우 세 건 다 2.0.0 릴리스 **이전에** 1.x 에서 수정됐고, 권고문의 영향 버전 범위(`< 1.23.0`, `< 1.27.2`, `< 1.28.1`)에 2.x 가 올라 있지 않다는 걸로 판정했다.

- CVE-2025-66416 — 기본값에서 Host/Origin 미검증(DNS rebinding) → 1.23.0
- CVE-2026-52869 — 세션을 session_id 만 보고 라우팅, 인증 주체 미검증 → 1.27.2
- CVE-2026-59950 — deprecated websocket 전송의 Origin 미검증 → 1.28.1

남은 의문: **"영향 버전 범위에 없다" 를 "그 수정이 들어 있다" 로 읽어도 되나.** 메이저가 갈라진 뒤 백포트만 되고 본류엔 없는 경우도 이론상 가능하니, 릴리스 날짜 순서(패치 → 메이저 릴리스)까지 같이 봐야 마음이 놓인다.
