# edge 방화벽 — VPN이 뚫어주지 않는 내부 접근

사내 내부 서비스(내부 MCP 서버 같은)에 접속하려고 VPN을 붙였는데 막혔다. 보안팀 답은 **"edge에서 허용 필요해요."** 헷갈렸던 건 하나 — **VPN 붙었으면 사내망 안이니 내부 서비스는 다 되는 거 아닌가?** 아니었다. **사내망에 "들어오는 것"과 그 안의 "특정 서비스에 닿는 것"은 다른 허가**다.

![[VPN vs edge 방화벽.svg]]

## 두 개의 관문

1. **VPN = 1차 관문(입장).** 인증을 통과하면 사내망 안의 **VPN 영역(zone)** 에 들어오고 VPN 클라이언트 IP를 받는다. 여기까진 됐다.
2. **edge 방화벽 정책 = 2차 관문(내부 접근).** VPN 영역에서 **그 특정 내부 서비스로 가는 트래픽을 허용**하는 방화벽 룰. VPN에 붙었다고 사내 모든 서버에 자동 접근되는 게 아니다 — 어디까지 갈 수 있는지는 정책으로 따로 통제한다(**최소 권한 / 세그멘테이션**). 기본은 차단.

## 내부 접속인데 왜 "edge"인가

여기가 유일하게 짚을 지점. `edge`는 원래 **사내망과 바깥의 경계 장비**를 뜻하는데, 지금은 *내부* 서비스로 가는 얘기다. 모순 같지만 아니다 — **VPN을 종단(termination)하는 그 경계 방화벽(cafe24는 FortiGate)이, 동시에 "VPN 영역 → 내부 서비스" 트래픽의 정책 검사 지점**이기 때문이다.

```
[내 맥] ─VPN 터널─▶ [ FortiGate = edge 장비 ] ─정책 통과 시─▶ [내부 서비스]
                     ① VPN 종단 = 입장 허가
                     ② 방화벽 정책 = VPN영역→서비스 허가   ← 여기서 막힘
```

VPN 트래픽이 들어와 "어디로 갈 수 있나" 심사받는 물리적 지점이 그 edge 장비라, 보안팀은 "edge에서 (정책) 허용"이라 말한 것. **바깥으로 나가는 egress가 아니다** — 방향은 사내망 *안쪽*(VPN 영역 → 내부 서비스)이다.

## 12살 비유 — 정문 통과 ≠ 모든 동 프리패스

- **VPN** = 아파트 단지 **정문**. 주민 인증하고 단지 안으로 들어옴.
- **edge 방화벽 정책** = 들어가려는 **특정 동의 현관 도어락**. 정문 통과했다고 아무 동이나 못 들어간다 — 그 동 도어락에 내 카드가 등록돼 있어야 한다.

VPN은 "단지 입장" 하나만 해결한다. 특정 동(내부 서비스)마다 **도어락 등록(edge 정책)** 이 따로 필요하다.

## 큰 그림에서의 자리

경계 장비가 트래픽을 **방향·영역(zone)별 정책으로 통제**한다는 그림 자체는 [[네트워크 경계 (ingress·egress·NAT)]]에서 본 것과 같다 — 거긴 *클러스터* 경계(ingress/egress), 여긴 *사내망* 경계(VPN 영역 → 내부 서비스). 스케일과 방향만 다를 뿐 "경계에서 정책으로 건다"는 뼈대는 하나다.

> 같은 단어 `edge`라도 [[컨트롤 루프]]의 **edge-triggered**(상태 변화 순간에 반응)와는 전혀 다른 뜻이다. 공통 뿌리는 "가장자리"뿐.

## 관련 노트

- [[네트워크 경계 (ingress·egress·NAT)]] — 경계에서 방향/zone별로 트래픽을 통제하는 같은 그림(클러스터 경계 버전)
- [[컨트롤 루프]] — 헷갈리기 쉬운 다른 뜻의 edge(edge-triggered)
- [[SSH]] — 원격 접속과 함께 엮이는 네트워크 경계 주제
