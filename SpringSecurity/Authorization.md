# Authorization

**"그거 해도 되냐"** 를 판정하는 단계. [[Authentication]] 이 만들어 둔 신원을 전제로만 성립한다 — 누구인지 모르면 무엇을 허용할지 정할 수 없다.

## 인증과 갈리는 지점

| | Authentication | Authorization |
|---|---|---|
| 묻는 것 | 너 누구냐 | 그거 해도 되냐 |
| 횟수 | 요청 초입에 **한 번** | 접근할 때마다 **매번** |
| 실패 응답 | 401 (누군지 모름) | 403 (알지만 안 됨) |

401 과 403 의 차이가 이 표를 그대로 옮긴 것이다. **"로그인했는데 왜 403 이지"** 는 모순이 아니라 정상 — 신원은 확인됐고 권한이 없는 것뿐이다.

## 어디서 판정하나

[[SpringSecurity]] 에서는 두 층에 걸쳐 있다. 필터 체인에서 URL 패턴 단위로 거르고, 컨트롤러에서 `@PreAuthorize` · `@RolesAllowed` 같은 어노테이션으로 메서드 단위로 다시 건다([[로그인]] 참조).

두 층을 두는 이유는 **거르는 단위가 다르기** 때문이다. URL 로는 "관리자 영역 전체" 같은 거친 경계를 긋고, 메서드에서는 "이 글의 작성자 본인인가" 처럼 데이터를 봐야 아는 조건을 건다. 후자는 요청 경로만으로는 판정할 수 없다.

## 같은 모양이 네트워크에도 있다

[[ACL]] 이 하는 일이 정확히 인가다 — 규칙 목록을 위에서부터 훑어 첫 일치로 허용/거부를 정하고, **어디에도 안 걸리면 거부**한다. 애플리케이션의 인가도 같은 뼈대다. 기본이 거부여야 안전하고, 규칙의 순서가 결과를 바꾼다.

계층만 다를 뿐 "신원을 전제로, 규칙 목록으로, 기본 거부" 라는 구조는 하나다.

> 상태: #wip — 역할(role) 기반과 권한(permission) 기반을 언제 갈라야 하는지는 아직 감이 없다.
