# git log 는 HEAD 에서 닿는 커밋만 본다

오늘 한 커밋을 세려고 `git log --since=...` 를 돌렸는데, 다른 worktree 에서 feature 브랜치에 쌓은 커밋이 하나도 안 나왔다. 커밋이 사라진 게 아니라 **안 보이는 곳에 있었던 것**이다.

## 지금 서 있는 곳에서 뒤로만 걷는다

`git log` 는 인자가 없으면 **HEAD 에서 출발해 부모를 따라 거슬러 올라가며** 닿는 커밋만 보여준다. 다른 브랜치 끝에 달린 커밋은 HEAD 의 조상이 아니니 그 길에 없다. [[squash 머지는 머지 안 됨으로 보인다]] 와 같은 축이다 — git 에게 "있다" 는 늘 **어느 ref 에서 닿느냐**다.

- 전부 보려면 `--all` — 모든 ref(브랜치·태그·원격 추적)를 출발점으로 삼는다
- 커밋이 어느 ref 를 타고 잡혔는지는 `--source` 를 주고 포맷에서 `%S` 로 본다

## worktree 는 창고를 같이 쓴다

worktree 는 작업 디렉터리만 여러 개고 **객체 저장소와 ref 는 하나를 공유**한다. `git rev-parse --git-common-dir` 을 각 worktree 에서 찍어 보면 같은 경로가 나온다.

그래서 worktree 마다 `git log --all` 을 돌려 합치면 **같은 커밋이 worktree 수만큼 중복**된다. 세는 단위는 worktree 가 아니라 공통 디렉터리 — 공통 디렉터리 하나당 한 번만 센다.

> 왜 여기 붙나: "보인다" 도 커밋 그래프에서 출발점이 어디냐로 정해진다
