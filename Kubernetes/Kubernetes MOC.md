# Kubernetes MOC

이 영역의 입구. 핵심 축은 **"선언하면 루프가 맞춘다"** — 원하는 상태를 적어두면 k8s 가 현재 상태를 거기에 끊임없이 수렴시킨다. 아래 노트 대부분이 이 한 문장의 각론이다.

## 읽는 순서

**뿌리 — 발상과 그 발상을 굴리는 기계**

1. [[Kubernetes]] — 선언형 + 자동 수렴. 나머지가 전부 여기서 파생된다.
2. [[컨트롤 루프]] — 그 발상을 실제로 굴리는 심장. 관찰 → 차이 → 행동을 무한히.
3. [[컨트롤 플레인]] — 루프가 사는 곳. 모든 것이 API Server 라는 유일한 정문을 통한다.

**워크로드 — 무엇이 뜨고, 어떻게 찾나**

4. [[Pod]] — 배포 최소 단위. 왜 컨테이너를 한 겹 더 감싸는가.
5. [[Deployment]] — Pod 는 소모품이다. "N개 유지 + 무중단 교체" 를 선언으로 바꾼다.
6. [[Service]] — Pod IP 가 계속 바뀐다. 고정된 이름 뒤에 숨긴다.

**조작과 경계**

7. [[kubectl]] — 사람이 그 정문을 두드리는 창구. 내부 컴포넌트와 같은 문으로 들어간다.
8. [[kubeconfig 와 컨텍스트]] — 그 창구가 어느 클러스터·자격·네임스페이스를 보는가.
9. [[네트워크 경계 (ingress·egress·NAT)]] — 패킷이 클러스터 문을 넘을 때 주소가 어떻게 바뀌나.

**자원과 스케일 — 얼마나 주고, 몇 개 띄우나**

10. [[리소스 requests와 limits]] — 바닥(스케줄러 장부·경합 시 몫)과 천장. 둘은 보는 주체부터 다르다.
11. [[CPU throttling]] — 천장의 실체. "100ms 마다 70ms", 평균이 낮아도 걸린다.
12. [[HPA]] — 파드 수를 조절하는 또 하나의 루프. 사용률의 분모가 requests 다.

3번까지가 "왜 이렇게 생겼나", 6번까지가 "무엇을 띄우나", 9번까지가 "어떻게 만지나", 나머지가 "얼마나 주나" 다. 급하면 1·2 만 읽어도 나머지가 대충 짐작된다 — 전부 같은 루프의 변주라서.

## 다음 가지 후보
