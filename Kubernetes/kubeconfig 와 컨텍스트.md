# kubeconfig 와 컨텍스트

[[kubectl]]은 명령을 칠 때마다 "어느 클러스터에, 누구 자격으로, 어느 네임스페이스를" 볼지 결정해야 한다. 그 정보를 담은 파일이 **kubeconfig**이고, 한 세트로 묶인 단위가 **컨텍스트(context)** 다.

컨텍스트 = **주소 + 열쇠 + 방 번호**가 한 장에 적힌 출입증.

```
NAME              CLUSTER      AUTHINFO   NAMESPACE
클러스터-A-dev     클러스터-A    dev-user   팀-네임스페이스
클러스터-B-dev     클러스터-B    dev-user   다른-네임스페이스
```

| 칸 | 의미 |
|---|---|
| **CLUSTER** | API Server 주소 — 어느 [[컨트롤 플레인]]에 말을 걸까 |
| **AUTHINFO** | 인증 정보(보통 ServiceAccount 토큰) — 누구 자격으로 |
| **NAMESPACE** | 기본 네임스페이스 — `-n`을 생략했을 때 보는 곳 |

kubectl은 "현재 컨텍스트" 하나를 보고 움직인다. 그래서 **컨텍스트를 착각하면 명령이 통째로 엉뚱한 클러스터에 간다.** 조회면 헛수고로 끝나지만 `delete`였다면 사고다. 클러스터가 하나뿐일 땐 존재조차 의식할 필요 없다가, 개발/스테이지/운영이 갈리는 순간 갑자기 중요해지는 개념.

## KUBECONFIG는 파일 하나가 아니라 목록이다

가장 크게 헤맨 부분. 기본 위치는 `~/.kube/config` 지만, 환경변수 `KUBECONFIG`에 **콜론으로 여러 파일을 이어 붙이면 kubectl이 그것들을 하나로 병합해서** 본다.

```sh
export KUBECONFIG=~/.kube/config:~/configs/클러스터-A-config:~/configs/클러스터-B-config
```

이걸 모르면 "클러스터를 추가하면 이전 게 사라지는 것 아닌가"라고 착각하게 된다. 실제로는 병합이라 둘 다 살아 있고, 컨텍스트 목록에 나란히 뜬다.

**여기서 얻은 교훈 하나.** 클러스터 접속 정보를 만들어주는 설치 스크립트가 `export KUBECONFIG=...` 를 셸 설정 파일에 넣어줬는데, 하필 **로드되지 않는 백업 rc 파일**(`.zshrc` 가 아니라 그 이전 버전 백업)에 적었다. 파일은 정상 생성됐고 export 문도 정상인데, 새 터미널에서는 아무 클러스터도 안 잡혔다.

증상만 보면 "인증 실패"나 "설정 생성 실패"로 오해하기 쉽지만, 실제 원인은 **설정이 어디에 적혔느냐**였다. 환경변수 문제를 볼 땐 값이 맞는지보다 *그 줄이 실제로 읽히는 파일에 있는지*를 먼저 확인하는 게 빠르다.

해결은 실제로 로드되는 rc 파일에서 config 디렉터리를 통째로 잡는 방식으로 했다. 파일을 하나씩 나열하지 않으니 나중에 클러스터를 추가해도 손댈 일이 없다.

```zsh
_kubecfgs=(~/.kube/config(N) ~/configs/*(N))
export KUBECONFIG="${(j.:.)_kubecfgs}"
```

## 전환하는 두 가지 방법

**① 기본값을 바꾼다** — 그 클러스터에서 여러 작업을 이어서 할 때.

```sh
kubectl config use-context 클러스터-A-dev   # 순정
kubectx 클러스터-A-dev                       # 단축
```

**② 이번 명령만 다른 데로 보낸다** — 다른 클러스터를 잠깐 엿볼 때, 스크립트 안에서.

```sh
kubectl --context 클러스터-B-dev get pods
```

②가 안전한 경우가 있다. 현재 컨텍스트를 건드리지 않으니, 작업하던 맥락을 잃지 않는다. 스크립트에서는 오히려 ②가 정석이다 — 실행 시점의 기본 컨텍스트가 뭔지 가정하지 않아도 되니까.

## kubectx / kubens — 기능이 아니라 마찰 제거

```sh
kubectx                 # 목록 + 현재 것 표시
kubectx <이름>           # 전환
kubectx -               # 직전 컨텍스트로 (cd - 처럼)
kubens <네임스페이스>     # 기본 네임스페이스 변경 → 이후 -n 생략 가능
```

둘 다 **kubectl로 전부 되는 일을 짧게 만든 것뿐**이다. 새로운 능력은 없다. 그런데도 쓸 가치가 있는 이유는, [[kubectl]] 노트에서 짚은 *"-n 빼먹기 / 클러스터 착각"* 사고가 **타이핑이 길어서** 생기기 때문이다. 긴 컨텍스트 이름을 매번 정확히 치는 대신 목록에서 고르면 오타로 엉뚱한 데 가는 일이 준다.

도구가 실수를 막는 방식이 "검증을 추가"가 아니라 "마찰을 줄여 확인을 습관화"하는 쪽인 게 재미있다.

## 조심할 것 — config 파일은 자격증명이다

kubeconfig 안에는 클러스터 접근 토큰이 그대로 들어 있다. 즉 **이 파일 하나면 그 네임스페이스에 대해 내가 가진 권한을 그대로 행사할 수 있다.** 코드 저장소 안에 두면 커밋에 섞일 위험이 있으니 홈 디렉터리 아래 별도 폴더에 두는 게 안전하다. 파일을 공유하거나 로그에 출력할 일이 생기면 토큰 부분을 반드시 가릴 것.
