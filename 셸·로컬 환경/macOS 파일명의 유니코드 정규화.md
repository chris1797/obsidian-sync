# macOS 파일명의 유니코드 정규화

한글 파일명을 디렉터리에서 읽어 와 텍스트에 적힌 이름과 비교했더니, 눈으로는 똑같은데 `==` 가 거짓이었다. 글자가 같아 보여도 **바이트가 달랐다.**

## 같은 글자, 두 가지 조립법

유니코드에서 "한" 은 두 방식으로 적을 수 있다.

- **NFC** — 완성형 한 글자 `한` (코드포인트 1개)
- **NFD** — 자모로 분해 `ㅎ + ㅏ + ㄴ` (코드포인트 3개)

화면에선 똑같이 그려지지만 문자열로는 다르다. 레고로 치면 통짜 블록 하나와 작은 블록 세 개로 같은 모양을 만든 것.

## APFS 는 무감하지만 보존한다

macOS 의 APFS 는 정규화에 **무감(insensitive)** 하다 — NFC 로 열든 NFD 로 열든 같은 파일이 열린다. 그런데 **보존(preserving)** 도 한다 — 저장된 그대로 돌려준다. 그래서 디렉터리를 나열하면 파일을 만든 쪽이 NFD 로 썼으면 NFD 가 나온다. 반면 내가 타이핑하거나 파일 안에 적힌 텍스트는 대개 NFC 다.

"열 수 있다" 와 "이름이 같다" 가 갈라지는 지점이다. 파일 시스템은 같다고 하는데 내 코드의 문자열 비교는 다르다고 한다. [[프로세스 환경은 시작할 때 복사된다]] 처럼, 겉으로 같아 보이는 두 사실이 실제론 다른 사실이었다.

## 비교 전에 맞춘다

```python
import unicodedata
unicodedata.normalize("NFC", a) == unicodedata.normalize("NFC", b)
```

양쪽을 같은 형식으로 맞춘 뒤 비교한다. 한쪽만 맞추면 반대쪽이 NFD 일 때 또 깨진다.

> 왜 여기 붙나: 파일 시스템이 실제로 들고 있는 이름을 가정하지 않는다 — 보이는 것과 저장된 것이 다르다
